# Руководство по стилю документации FileTransfer

Руководство устанавливает единые правила написания и оформления документации
проекта FileTransfer — асинхронной клиент-серверной системы удалённой передачи
файлов изображений (C++, Qt/QML, gRPC).

## Область действия

Руководство применяется к следующим документам проекта:

| Вид документа | Где хранится | Основной читатель |
| --- | --- | --- |
| README компонентов | Корень репозитория и каталоги `server/`, `client/` | Разработчик |
| Описание gRPC-интерфейса | `docs/api/` | Разработчик клиента или интеграции |
| Инструкция оператора | `docs/user/` | Оператор |
| Руководство по установке и настройке | `docs/admin/` | Системный администратор |
| Отчёты, ТЗ и ПМИ по ГОСТ | `docs/reports/` | Преподаватель, заказчик |
| Сообщения коммитов и описания Pull Request | GitHub | Команда проекта |

Для документов, оформляемых по ГОСТ (отчёт, ТЗ, программа и методика испытаний),
требования ГОСТ имеют приоритет над этим руководством. Руководство дополняет ГОСТ
в вопросах, которые стандарт не регулирует: тон, терминология, примеры, оформление
кода.

## Цели

- Единообразие: документы разных авторов выглядят и читаются одинаково.
- Скорость: автор не тратит время на решение уже решённых вопросов.
- Понятность: читатель быстро находит нужное и выполняет действие без ошибок.
- Проверяемость: часть правил проверяется автоматически линтером в CI.

## Нумерация правил

Каждое правило имеет идентификатор, например `ТН-1` или `КД-3`. На идентификатор
ссылаются в комментариях к Pull Request: «Нарушено правило ТН-2».

| Префикс | Раздел |
| --- | --- |
| ТН | Тон и голос |
| ЯЗ | Язык и грамматика |
| ОП | Орфография и пунктуация |
| ТР | Терминология |
| СТ | Заголовки и структура |
| СП | Списки и таблицы |
| КД | Код и идентификаторы |
| РС | Рисунки и ссылки |
| ИН | Интерфейс и сообщения об ошибках |
| ЧС | Числа, даты и единицы |
