# Как пользоваться руководством

## Автору документа

1. Перед началом работы выберите шаблон в разделе «Шаблоны».
2. Пишите текст, сверяясь с разделами «Стиль изложения» и «Оформление».
3. Перед отправкой изменений запустите проверки локально:

    ```bash
    npx markdownlint-cli2 "docs/**/*.md"
    python scripts/check_terms.py docs
    mkdocs build --strict
    ```

4. Пройдите контрольный список ниже.

## Ревьюеру

При замечании указывайте идентификатор правила и предлагайте исправление:

```text
ТР-2: вместо «скачка» используйте «загрузка». Предлагаю: «Загрузка файла прервана».
```

## Контрольный список автора

- [ ] Цель документа и читатель указаны в первом абзаце.
- [ ] Инструкции написаны в повелительном наклонении (ЯЗ-1).
- [ ] Термины совпадают с глоссарием (ТР-1).
- [ ] Имена методов, файлов и параметров оформлены как код (КД-1).
- [ ] У каждой таблицы и каждого рисунка есть подпись (СП-4, РС-1).
- [ ] Линтер и сборка проходят без ошибок.

## Если правила нет

Если вопрос не решён в руководстве:

1. Посмотрите, как он решён в существующих документах проекта.
2. Если единого решения нет — примите решение и создайте Issue с предложением
   нового правила.
3. Для общих вопросов русского языка используйте справочник Д. Э. Розенталя,
   для вопросов технического стиля — Google Developer Documentation Style Guide.
