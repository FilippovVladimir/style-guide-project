# Заголовки и структура

## СТ-1. Структура документа

Каждый документ начинается с заголовка первого уровня и вводного абзаца,
в котором указаны назначение документа и читатель. Далее — разделы
в порядке, заданном шаблоном.

## СТ-2. Один заголовок первого уровня

В файле Markdown допускается один заголовок `#`. Уровни заголовков не
пропускайте: после `##` идёт `###`, а не `####`.

## СТ-3. Формулировка заголовков

- Заголовок — существительное или инфинитив, без точки в конце.
- Заголовок раздела-инструкции — инфинитив: «Загрузить файл»,
  «Настроить сервер».
- Заголовок справочного раздела — существительное: «Параметры запроса»,
  «Коды ошибок».
- Длина заголовка — не более 7 слов.

| Так | Не так |
| --- | --- |
| Отменить загрузку | Как можно отменить загрузку файла, если она идёт слишком долго? |
| Коды ошибок | Ошибки, которые могут произойти. |

## СТ-4. Один файл — одна тема

Если раздел длиннее трёх экранов, вынесите его в отдельный файл и добавьте
в навигацию `mkdocs.yml`.

## СТ-5. Имена файлов

Имена файлов документации — латиницей в нижнем регистре через дефис:
`operator-instruction.md`, `rpc-method.md`.

## СТ-6. Выделения

- **Полужирный** — только для важных предупреждений внутри абзаца.
- *Курсив* — для первого упоминания термина.
- Подчёркивание и ПРОПИСНЫЕ буквы для выделения не используйте.
- Важные предупреждения оформляйте блоками `!!! warning`.

!!! warning "Пример предупреждения"
    Удалённый файл нельзя восстановить средствами клиента.
